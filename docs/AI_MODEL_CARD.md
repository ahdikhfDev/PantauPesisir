# AI model card — `cews-iforest-v1`

> **Model type:** prototype anomaly-screening model. It is not a tsunami detector, not a hazard
> probability model, and not certified or validated for operational use.

## 1. Purpose

Score how unusual a short window of coastal buoy telemetry is **relative to its own recent
behaviour**, so an operator can see whether something changed in the last hour. A separate,
transparent rubric grades absolute severity. The model is one input to a prototype decision-support
view — never the decision itself.

## 2. Intended use

- Demonstration and education for IT RUSH 2026.
- Screening synthetic buoy telemetry generated by the CEWS simulator.
- Showing judges and users a complete, explainable ML pipeline with real training data and honest
  evaluation.

## 3. Out of scope / prohibited use

- Tsunami detection, warning issuance or evacuation guidance.
- Emergency response, navigation, search-and-rescue or insurance decisions.
- Predicting fish prices, income, market demand or any economic outcome.
- Claiming operational readiness or scientific validation.
- Inferring wave height, bathymetry or currents from optical satellite imagery.

## 4. Training data

| Item | Value |
| --- | --- |
| Dataset | NOAA NDBC historical standard meteorological data (`stdmet`) |
| Provider | NOAA National Data Buoy Center |
| Access | Public archive, no authentication (`https://www.ndbc.noaa.gov/data/historical/stdmet/`) |
| Licence | Public domain (U.S. federal government work) |
| Stations | 51002 (SW Hawaii, 17.070 N 157.755 W) and 41010 (Canaveral East, 28.860 N 78.478 W) |
| Years | 2022–2024 |
| Valid rows | 41,104 |
| Cadence | ~10 minutes, sensor outages preserved |
| Retrieval date | 2026-11-18 |
| Provenance file | `backend/ml/data/ndbc_wave_training.provenance.json` |

Rows missing any core variable (wave height, period, wind speed, wind direction, pressure, sea
temperature) were removed; NDBC sentinel values (99/999/9999) were removed first.

**Domain gap:** training stations are offshore US waters. The prototype applies the model to
simulated Indonesian coastal buoys. This is a deliberate, disclosed limitation; the model learns
*relative* behaviour to reduce regime sensitivity, but it is not a substitute for local training
data.

## 5. Features (11, trailing only)

| Feature | Rationale |
| --- | --- |
| `wave_height_m` | Absolute sea-state level |
| `air_pressure_hpa` | Absolute pressure level |
| `wave_height_rel_dev` | (H − 6-sample mean) / mean — local change |
| `wave_steepness_rel_dev` | Steepness vs its recent mean |
| `wind_speed_rel_dev` | Wind vs its recent mean |
| `wave_period_rel_dev` | Period vs its recent mean |
| `pressure_residual_hpa` | Pressure minus 6-sample mean |
| `pressure_rate_hpa_per_hour` | Cadence-normalised pressure tendency |
| `wave_height_change_ratio` | One-sample relative wave change |
| `sst_residual_c` | SST minus recent mean |
| `wave_direction_change_deg` | Absolute angular change per sample |

Rolling statistics use a 6-sample trailing window (`min_periods=2`). Features never look forward, so
a chronological split does not leak future information.

**Why relative features:** the first iteration used absolute period, steepness, SST and directional
encodings. Those encode open-ocean climatology, so every normal tropical-bay window was flagged as
maximally anomalous (severity 1.0). The redesign measures local departure and keeps absolute
severity for the rubric. This is documented rather than hidden.

## 6. Training procedure

- Chronological 80/20 split by time: **32,883 train / 8,221 validation** rows.
- Train period: 2022-01-01 → 2024-09-16 (UTC). Validation: 2024-09-16 → 2024-12-31 (UTC).
- Pipeline: `SimpleImputer(median)` → `StandardScaler` → `IsolationForest`.
- `n_estimators=250`, `contamination=0.01`, `max_samples="auto"`, `random_state=42`, `n_jobs=-1`.
- Preprocessing is fitted on the training slice only.
- Environmental versions: scikit-learn 1.9.1, pandas 3.1.1, numpy 2.5.4.

## 7. Threshold calibration

The raw Isolation Forest score distribution on simulated coastal telemetry differs from the training
distribution, so the operating threshold is calibrated on **90 normal-scenario windows**
(3 zones × 30 deterministic seeds, 18 samples at 5-minute spacing):

- target flag rate: 10%
- observed flag rate on those windows: 10%
- threshold stored in the artifact; the API reports it as severity 0.50 via a logistic mapping where
  the median normal window maps to 0.10.

This is a **scenario-calibrated demonstration detector**. Flag rates on real coastal telemetry would
require recalibration with real data.

## 8. Evaluation (real validation slice)

| Metric | Value |
| --- | --- |
| Rows flagged at deployed (scenario-calibrated) threshold | **0.16%** |
| Proxy recall: top-5% rapid pressure changes at a 1% reference threshold | **6.47%** |
| Proxy recall: top-5% rapid one-step wave-height changes at the same reference | **2.19%** |
| Random-selection baseline at that reference threshold | **1.01%** |
| Median wave height of flagged rows | **6.29 m** |
| Median wave height of unflagged rows | **2.12 m** |
| Observed wave height p95 in validation | 3.68 m |

Interpretation: flags are enriched in rapid-change and high-wave events relative to random, and
flagged rows are much rougher than typical rows. Discrimination is **modest**, not strong. There are
no hazard labels, so recall/precision against "dangerous conditions" cannot be computed and is not
claimed.

Behaviour check on deterministic simulator windows (20 seeds per scenario, 3 zones):

| Scenario | Windows flagged (severity ≥ 0.5) | Median severity |
| --- | --- | --- |
| normal | ~10% | 0.13 |
| warning | ~40% | 0.28 |
| extreme | 100% | 0.95 |

The warning scenario is intentionally not always flagged by the *behavioural* model; the absolute
risk rubric still raises warning-level windows to moderate/high. This separation is a feature, not a
bug: an unusually steady but severe sea state is not a behavioural anomaly.

Reproduce with `python backend/scripts/check_model_behavior.py`.

## 9. Outputs

Each `analyses` run stores:

- observation window, number of scored windows, input observation IDs
- anomaly flag, score (0–1), calibrated threshold
- risk score/level and rubric version
- top contributing factors (value, unit, baseline mean, standardised deviation)
- explanation and recommendation text
- data-quality summary (sampling, completeness proxy, simulated share, satellite association)
- caveats and `is_simulated`

## 10. Risks and ethical considerations

- **False reassurance:** a low score does not mean safe conditions.
- **False alarm:** a high score may reflect a sensor artefact or a benign fluctuation.
- **Automation bias:** the UI labels every output as prototype decision support and tells users to
  consult BMKG/BPBD.
- **Domain shift:** training stations differ from Indonesian coastal waters; no local validation.
- **Simulated input:** the system can be demonstrated without deploying hardware, but it cannot be
  used to infer real sea conditions.

## 11. Reproducibility

```bash
cd backend
python scripts/fetch_training_data.py     # downloads NDBC archives (public)
python scripts/train_model.py --version cews-iforest-v1
python scripts/check_model_behavior.py
python -m pytest -q                        # includes model/feature tests
```

Artifacts:

- `backend/ml/artifacts/cews-iforest-v1.joblib` (committed, 2.2 MB)
- `backend/ml/artifacts/cews-iforest-v1.metrics.json`
- registry row in `ml_models` (seeded or written by the training script)

## 12. Versioning and maintenance

- Version string: `cews-iforest-v1`; model URI and feature names stored with the artifact.
- `ml_models` keeps algorithm, feature schema, training period, metrics and active flag.
- Changing features, calibration or training data requires a **new version string** and a new model
  card section; never overwrite silently in an operational setting.
- Next steps with real value: local Indonesian buoy/CMEMS training data, supervised labels derived
  from official advisories, drift monitoring, and recalibration against measured flag rates.
